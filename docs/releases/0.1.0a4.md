# ForgeUI 0.1.0a4

This release hardens request limiting, backs off the idle job worker, drops the editable Docker
install, and raises `services/actions.py` unit coverage to 97%.

Implemented: `RequestLimitMiddleware` is rewritten as a pure ASGI middleware instead of patching a
private Starlette request attribute — it rejects an oversized `Content-Length` up front and turns
an over-limit streamed body into the same 413 unless the response has already started. The
in-process job worker backs off its idle poll from 0.1 s to a 2 s cap while the queue is empty and
resets on a claimed job, instead of running a claim query ten times a second. The Docker build now
installs the project non-editable, so the runtime stage no longer needs a `PYTHONPATH` override or
a second copy of the source tree. New unit tests cover the increment, append, update-collection and
delete-collection state actions, toast, navigate, refresh, modal and capability results, the
transient-mode guards, and the version-conflict path. The publish workflow also accepts manual
`workflow_dispatch` runs on a pushed tag and retries publishing an already-released version
instead of failing.

No runtime dependencies were added. The wheel budget stays 144 KiB. Base and app-extra wheel
installations were smoke tested in a fresh environment.

(environment mismatch noted above).

## Boundaries

The Docker non-editable install and `RequestLimitMiddleware` rewrite were validated by the non-
browser unit/integration/security suite and static analysis in this pass, not by a live Docker
build or a running container in this environment. The browser-driven analytics regression test
was not exercised this release due to the local Playwright browser revision mismatch; it is
unrelated to the shipped code changes. The publish workflow's new `workflow_dispatch` trigger and
`skip-existing` publish behavior were checked by YAML parsing and manual review only — they were
not exercised end to end on GitHub Actions as part of this preparation step, which stops short of
tagging or publishing.

See [distribution](../distribution.md) for the updated manual-dispatch publishing step.
